# 内核契约

内核是 `kernel/`（Rust，`wasm32-unknown-unknown`，wasm 上 `no_std`，零依赖）。它不知道 DOM、时钟、网络和文字；它只有 64 个整数、一个带种子的随机数发生器，以及「做一件事并说出发生了什么」的命令。界面经 `src/kernel/kernel.ts` 调用它。

构建：`npm run kernel`（先由 `data/rules.json` 生成 `kernel/src/tables.rs`，再 `cargo build --release --target wasm32-unknown-unknown`，最后把 wasm 以 base64 写进 `src/kernel/kernel.wasm.ts`）。内联是因为安装进桌面的应用跑在 opaque origin 的沙箱框里，不依赖对自身文件的 `fetch`。

体量：wasm 12,380 字节；`data/rules.json` 约 11 KB。合计远小于 400 KB 的上限。

## 与提示词的差异

| 提示词 | 实际 | 原因 |
|---|---|---|
| `new_game(name)` | `bf_new_game(seed, hacker)`；大名由界面保管，和快照一起存 | 内核不碰字符串；名字不影响任何规则 |
| `spend_day(choice)` | 没有 | 原版没有「原地过一天」。`0x40a0d0`（过一天）只被十个站点按钮调用；「买车票／洗脸／小睡一觉／吃街头烤红薯／喝汽水」是定时器对话框里的一组过场串，不是选项，也没有回血规则。不凭空加规则 |
| `move(station)` | `bf_move(place)`，place 为 1–10 | 同原版字段 `0x760` |
| `visit(venue, args)` | `bf_visit(venue, argument)` | 一个整数参数就够 |
| `end()` | `bf_end()`：提前离开北京，不计分 | 对应「逃离北京」 |

## 导出函数

| 函数 | 作用 | 返回 |
|---|---|---|
| `bf_buffer() -> *u8` | 512 字节的交换缓冲区 | 指针 |
| `bf_state() -> *i64` | 状态槽（64 个 i64，只读视图） | 指针 |
| `bf_events() -> *i64`、`bf_event_count() -> i32` | 上一条命令发生的事，每条 4 个 i64：`kind, a, b, c` | — |
| `bf_set_scores()` | 从缓冲区读 10 个 i64（高到低），作为本地高手榜 | — |
| `bf_new_game(seed: u32, hacker: i32)` | 开局：2000／5000／100／40 天，掷价、结一次息（欠债显示 5500） | — |
| `bf_snapshot() -> i32` | 把状态写进缓冲区 | 字节数（512） |
| `bf_restore(len: i32) -> i32` | 从缓冲区读状态并校验 | 错误码 |
| `bf_move(place: i32) -> i32` | 去 1–10 号地方，过一天 | 错误码 |
| `bf_max_buy(item: i32) -> i32` | 现在最多能买几个 | 数量；负数为 −错误码 |
| `bf_buy(item, quantity) -> i32`、`bf_sell(item, quantity) -> i32` | 买进（加权平均成本）／卖出 | 错误码 |
| `bf_rent_quote() -> i64` | 中介报的价（实收多 2000） | 元 |
| `bf_visit(venue: i32, argument: i64) -> i32` | 1 存钱、2 取钱、3 医院（点数）、4 邮局（还多少）、5 租房（1 成交／0 不租）、6 网吧 | 错误码 |
| `bf_set_option(option, value) -> i32` | 1 允许黑客攻击银行网络；2 地面图 | 错误码 |
| `bf_end() -> i32` | 逃离北京 | 错误码 |

每条命令开头清空事件表。被拒绝的命令不改状态。

## 状态槽（快照结构）

快照就是 64 个小端 i64，共 512 字节，槽位固定：

| 槽 | 内容 | 槽 | 内容 |
|---|---|---|---|
| 0 | 魔数 `0x424A465300000001`（"BJFS"＋版本 1） | 12 | 所在地 0／1–10 |
| 1 | 随机数状态 | 13 | 0 地铁图／1 地面图 |
| 2 | 0 未开局／1 进行中／2 结束 | 14 | 去过几次网吧 |
| 3 | 结局：1 遣送／2 登榜／3 没进前十／4 倒在街头／5 逃离 | 15 | 允许黑客 |
| 4 | 剩余天数 | 16 | 名声提示是否说过（位 0 禁书、位 1 假白酒） |
| 5 | 现金 | 17 | 已过的回合 |
| 6 | 欠债 | 18 | 结局净值 |
| 7 | 存款 | 19 | 名次 1–10 |
| 8 | 健康 | 20 | 称号 0–4 |
| 9 | 名声 | 21 | 开局种子 |
| 10 | 出租屋容量 | 24–31 | 八种货的黑市价格（0＝缺货） |
| 11 | 已放件数 | 32–39／40–47 | 数量／买进价格 |
| 48–57 | 高手榜十个分数 | 其余 | 0 |

`bf_restore` 校验魔数、各字段范围、以及「数量之和＝已放件数」；不合格返回 4，不改现有状态。金额用 i64（原版是 32 位 int，极端情况下会溢出；这是唯一一处有意不复刻的行为）。

界面存档是一个 JSON：`{ v: 1, name, kernel: <base64 512 字节>, marks, ground }`，经 bridge 的 `state.set("save", …)` 保存；高手榜另存 `state.set("scores", …)`。没有第二份可写状态：界面每次都从内核读。

## 错误码

0 成功；1 不在游戏中；2 参数不对；3 已经在这一站；4 快照无效；10 今天缺货；11 现金不够且没存款；12 现金不够、去取钱；13 屋子满；14 数量不对；20 没有这种货；21 这里没人做这生意；30 银行金额不对；40 很健康（挂神经科）；41 钱不够治；51 还不起；60 房子已最大；61 没有三万；70 进网吧要 15 元；71 网吧去太多。

## 随机数与种子

复刻原版链接的 Visual C++ 6 `rand()`：`state = state × 214013 + 2531011`，取 `(state >> 16) & 0x7FFF`；区间一律 `rand() % N`，调用顺序与原函数一致（掷价 8 次 → 缺货 0／3 次 → 行情 18 次 → 掉血至多 12 次 →（昏迷 3 次）→ 掉钱至多 7 次 → 黑客 1 次＋）。原版用 `srand(time(0))`，所以没有「原版的某一局」可对；这里种子显式给出：新游戏时界面用 `crypto.getRandomValues` 取一个 32 位种子传入，种子存在槽 21。

## 数据表格式

`data/rules.json`（由脚本从 Beijing.exe 数据段导出，未手改）：`start`、`interest`、`stockout`、`items[8]`（`base`,`span`,`fameOnSell`）、`market[18]`（`n`,`item`,`mul`,`div`,`add`,`debt`,`text`）、`health[12]`（`n`,`damage`,`text`）、`money[7]`（`n`,`percent`,`target`,`text`）、`coma`、`beating`、`hacker`、`hospital`、`rent`、`netcafe`、`fameTiers`、站名、昏迷地点、称号、默认高手榜。每一条带 `source`（`notes/RE-笔记.md` 第 4 节＋exe 地址）。内核只读数字；文字由界面从同一份文件读，所以数字和文案不会对不上。

## 测试

`kernel/tests/kernel.rs`（`cargo test --release`，12 项）：

- 发生器等于 VC6 `rand()`（`srand(1)` 的前五个数 41、18467、6334、26500、19169）。
- **同一颗种子、同一串命令，两次运行的快照逐字节一致**；换一颗种子则不同。
- 中途存档再读回，之后每一步的快照与原局逐字节一致；坏快照被拒。
- 固定脚本跑完 40 天到达三种结局：种子 1 的买卖人登榜（净值 1,688,902，第 2 名）；种子 8 的闲人被遣送（净值 −176,102）；种子 1 的闲人倒在街头（还剩 2 天）。
- 价格区间、缺货不超过 3 种、事件频率、买卖的各种拒绝、名声、五个机构的收费、欠债过十万挨揍、结局后不再动。

`tests/unit/kernel.test.ts`（Vitest）在 JS 一侧对编译出的 wasm 再做一遍「同种子两次运行逐字节一致」。
